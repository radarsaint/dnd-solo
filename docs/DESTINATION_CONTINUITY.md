# Warned-room transition and source preparation

The source-case move initially failed because every generated connection assumed the destination contained a reciprocal arrival area. The index deliberately does not infer reverse exits. The compiler now targets the existing reciprocal threshold only when indexed; otherwise it targets the destination's main area. It does not invent a reverse exit. A legacy cached link can resolve a missing old anchor only after matching the pinned source, indexed outgoing connection, destination identity and canonical path. Generic broken links still fail. A compatibility resolution is recorded in room state; old source files are not rewritten.

Established destination warnings now reach the initial source-reading packet as well as later private planning. Their dynamic context is separate from the source request hash and remains protected by the existing revision-bound pending commit. Optional actor visibility corrections require full source-sentence evidence, persist in the initial interpretation and leave source files intact. They cannot undo a dead or fled actor outcome. Source interpretation is bookkeeping: it must not consume a player turn or invalidate the room's first-entry guard. That classification error was found during the real transition test and corrected; the opening guard was not relaxed.

The targeted final suite passed 243 tests. It covers imported adventures, hostile draft validation, PDF ingestion, room loading, source interpretation, timed procedures, visibility, warning/revisit integration, agent lifecycle, party mechanics and native combat. A Windows-specific expected command in the existing adventure test now accounts for shell quoting; production command quoting was not changed. Python 3.8 syntax checks passed, not interpreter execution.

A fresh private run replayed source interpretation, initial entry, native combat start, initiative, departure/warning, two rounds, return, reported spell attacks, native combat end, normal exit, destination interpretation and destination entry through the public bridge. Database connections were reopened between turns. The warning reached both interpretation and planning; concealed identity stayed out of narration. Entry replay was idempotent, and a second opening was refused unchanged. The successful run used no engine fallback. Earlier failed host narration and fallback attempts are retained separately; the host output was corrected to respect the existing progressive reveal and Kit-question requirements, rather than changing those validators.

Host decisions and player reports were authored test inputs; NPC d20s were pinned to one. This is not an autonomous host evaluation. The actual source case proves transition and context delivery through the compiled connection, not adjacency from the original map. Prior destination state and warning preservation are checked with a separate synthetic engine-level round trip; the actual case did not have a source-grounded return route and was not forced into one.

Remaining source-fidelity gaps discovered at the destination: a named combatant lacks its native statistics, a visible captive exists only as a fact and not as an actor, and a creature's source-specific HP override is lost. They are explicit unresolved items, not fixed by a successful transition. Earlier experimental saves whose source interpretation consumed a room turn were not silently rewritten; the acceptance used a fresh save. No deployment or full-runtime-readiness claim follows from these tests.
