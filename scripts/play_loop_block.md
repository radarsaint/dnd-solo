## During play: run the commands, never read the runtime (hard rule)

- **Per-turn contract: [docs/PLAY_CARD.md](docs/PLAY_CARD.md).** Read it once at mount (it is also `play_card` on the opening packet). Do not reread repo docs, the runtime, or a log during play. One player message is one prepare and one complete. A rejection's `Fix:` line is the only edit; complete that same `turn_id` once. A committed roll_call, clarify, risk_confirm, or reaction is a complete turn: show `spoken` and stop.
- **Never open, search, or inspect runtime source, schemas, or tests during play.** The packet tells you everything a turn needs. If something is unclear, follow the packet's instructions or `retry_instruction`, or run `rehydrate`. Each command takes about 0.1 s; slow turns come from reading code.
- **Per turn, exactly this:**
  1. Write the player's exact words to `a.txt`, then run `python3 -m runtime.kit_agent prepare --one-pass --db kit.sqlite --action-file a.txt`
  2. Write one JSON object `{"decision", "performance", "manifest"}` to `o.json`, following the packet. `manifest` is only `{"session": "<hash>", "room": "<hash>"}`. Copy filled examples from `shapes`.
  3. Run `python3 -m runtime.kit_agent complete --db kit.sqlite --turn-id <turn_id> --input-file o.json`. If accepted, show only `spoken`. If rejected, paste `fix` and complete the same `turn_id` once. Do not prepare again.
- **If `prepare` returns `turn_pending`:** a turn is already waiting and nothing was recorded. Run its `next_command` (the `complete` for that `turn_id`). A bare yes completes the pending opening: prepare returns `spoken` and you show it. It is never an in-fiction action. Do not draft a decision for it.
- **Adventures:** `start` lists playable modules in `modules_available`. If the player supplies an adventure PDF, one host step: `python3 -m runtime.kit_agent ingest <file>` (built-in text layer; it indexes the book and compiles the first scene). Then run `python3 -m runtime.kit_agent status --db kit.sqlite` and, when the player says begin, run its `next_command` (`start --room` of that first scene). Pasted text: save it as `adventure.txt` (page breaks as form feeds; boxed read-aloud lines keep the `> ` prefix) and run `python3 -m runtime.kit_agent adventure import --db kit.sqlite --text-file adventure.txt`. A PDF with no text layer is refused in one line; ask them to paste the text. `pdftotext -layout` or `pypdf` run only if the built-in reader cannot read the text layer. Locations after the first compile themselves on arrival. If import refuses, say in one line what is missing. Never build rooms, NPCs, stat blocks, or a module yourself, and never edit compiled rooms.
- **Party companions:** not supported yet. (Planned: Kit plays a party member from that member's own sheet, without her DM knowledge.) Say so in one line. Never fake a companion, and never size the party or encounters to a published adventure's party. The party is the player's own character(s).
