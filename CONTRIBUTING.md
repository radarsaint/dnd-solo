# Contributing

Keep changes narrow and testable.

- Put behavioral preference changes in `docs/personality/`.
- Put generic runtime contracts/code in `docs/architecture/` and `runtime/`.
- Put campaign-specific logic in `docs/campaign/` or campaign data modules.
- Add/update stable IDs whenever maps or art are introduced.
- Add a behavioral scenario when fixing a recurring DM failure.
- Prefer architecture decisions over adding exceptions to giant prompts.
